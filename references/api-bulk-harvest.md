# 数据型站点 API 批量采集（题库/列表/表格 SaaS）

> 适用：目标不是"读一篇文章"，而是把一个数据型站点的结构化记录**全量拉进本地库**（题库、商品、表格列表）。
> 与单页 scrape / 全站 crawl 并列的第四类活。拆解字段加密/混淆归 G-zhen-nixiang；本文件只讲"接口摸清后怎么稳、全、对得上账地拉"。

## 1. 先摸清接口（浏览器，不靠猜）

1. MCP 浏览器 `new_page` 打开 → `list_network_requests(resourceTypes:["xhr","fetch"])` 看列表请求。SPA 首页常先打 `/api/init`、`/api/site/slug/<x>` 再打列表接口。
2. `list_network_requests(reqid)` 读 **请求体（分页协议）+ 响应头**。关键确认：
   - 方法/路径、`pageNum/pageSize`（或 page/size）字段名、空间/分类 id 字段。
   - **pageSize 上限要实测**：常见硬上限 100；传 200 服务端可能返回空/"服务未返回数据"（HTTP 仍 201），不能只看状态码。
3. 响应整体明文、但**个别字段是密文/混淆**时，交 G-zhen-nixiang 还原，拿到本地 decode 函数后再入库（见其 SKILL 的 Capture 路线）。
4. 鉴权：先看无 token 能否直连（curl 试一次）。需要登录态时，在已登录页面用 `evaluate_script` 把 `localStorage` 里的 JWT/设备 id **写到 outputFile**（绕开聊天上下文），脚本从文件读，用完即删；token 不入笔记/git/报告。

## 2. 本地批量拉取器（写一次脚本，别在浏览器里翻几万页）

浏览器 evaluate 有 ~30s 超时且页面一旦导航，注入的 in-page 抓取器与内存全部销毁（"execution context destroyed"）。**全量任务一律本地 Python**：

- 并发 3~6（别贪高，会 429）；每页间 0.2s 左右礼貌间隔。
- **指数退避重试**（如 1.2×(n+1) 秒，最多 6 次）：实测能把偶发 429/超时全部兜成 0 失败。
- **断点续传**：按页存独立文件 `page_0001.json`（先写 `.part` 再 `os.replace` 原子改名）；已存在且大小>0 就跳过。中断重跑只补缺页。
- 完成后产出 `_failed.json`：区分源站 404（记录永久缺失）与网络失败（再跑一轮）。
- 先小规模冒烟（3 页）确认协议/字段，再放全量。

## 3. 文件/图片资源下载

- 先探测裸链：很多 CDN/对象存储 403 只是缺 **`Referer: https://<域>/`**（必要时加常规 UA），加上即 200，未必需要 token。
- 文件名做安全化（`\\/:*?"<>|`→`_`），大小校验等于远端 `size` 才算成功，保留 `.part`→原子改名。
- 图片若被题目正文以 `{image/xxx.png}` 之类标记引用，**下载时保留标记里的相对路径**（`data/images/image/xxx.png`），保证题文标记能直接拼出本地文件，不要重新命名成无关联的散文件。

## 4. 对账本是硬要求（G 先生明确要求：下载物必须彼此对得上账，不能"谁是谁的答案/图分不清"）

任何成规模下载，除原始数据外**必须再产一个独立的 manifest 库/表**（重建产物，只读原始库、不手改），让每条下载物可**双向溯源**：

- **题↔答案/解析**：题干、标准答案、分步解析常分布在不同字段（如 `result`/`fenxi`/`analysis_list`）；同一 `_id` 同行，天然归属。判定"有无答案"要把几个字段一起看——只看一个字段会严重低估覆盖率（实测某竞赛库 result 仅 22%，但 analysis_list 95%，答案在分步解析里）。
- **题↔图↔字段**：建 `question_image_ref(question_id, field, image_path)` 多对多关系（图可能被多题共用、出现在题干/答案/解析不同字段）；`image(path, local_exists, size, status, ref_count)`。
- **资源文件↔记录↔目录**：远端记录（id/path/name/size/目录名）对本地文件（name/size/**sha256**/status）。
- **status 口径**：`ok`（在且大小一致）/ `pending`（未下）/ `size_mismatch` / `failed_404_or_network`；另计磁盘孤儿（下载了但无任何记录引用）。
- 每次重建写 meta（时间戳+各计数）。**对账脚本能抓到真实错误**：曾因图片相对路径基准写错，导致全部误判 pending + 8892 张误报孤儿——这正是账本的价值，不是走过场。
- 交付前跑双向抽查：题→图→本地文件、本地文件→题、文件→记录/sha256、成对版本（学生版/教师版、原卷版/解析版）各自可辨。

## 5. 完成判据

- 拉取页数/条数与接口 `total` 一致；`_failed` 中网络失败为 0（404 单列说明）。
- manifest 重建：磁盘孤儿 0、大小不符 0；双向抽查通过。
- token 中转文件已删；原始库与账本库分开、原始库只读。
